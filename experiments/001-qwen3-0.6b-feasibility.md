# 001: Qwen3-0.6B attribution feasibility

Date: 2026-09-12
Machine: worker-1, single RTX 4090 (24564 MiB), torch 2.14.0+cu130, circuit-tracer 0.5.0

## Question

Does circuit-tracer generate an attribution graph end to end inside 24 GB? Upstream issue #92
reports out-of-memory failures on larger cards, so this needed measuring rather than assuming.

## Command

    python -m circuit_tracer attribute \
      -t mwhanna/qwen3-0.6b-transcoders-lowl0 \
      -p "The capital of the state containing Dallas is" \
      -o spike_out/graph.pt \
      --dtype bfloat16 --verbose

## Result: passes

## Notes

Headroom is comfortable at under half the card, so the OOM reports in #92 must concern larger models
or wider feature configurations rather than this tier.

Download size is the real constraint, not VRAM. The repo holds 52.4 GB total but attribution pulls
only the 18.8 GB of transcoder weights; the remaining 33.6 GB under `features/` is needed only by
the visualisation server.

The top predicted token was id 279 at p=0.11, which is " the" rather than "Austin". Two causes, both
benign for an infrastructure test: Qwen3-0.6B is small, and the tokeniser prepended `<|im_end|>` to
the prompt. Subsequent work should use Gemma-2-2B, which is circuit-tracer's reference model and
whose transcoders come from GemmaScope.
